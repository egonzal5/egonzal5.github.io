Recursion Exercise (Due Fiday, May 8th, 11:55 pm)

Objectives

To practice writing recursive methods.

Overview

For this assignment you will implement a set of recursive methods processing strings and arrays. One of methods (replaceCells) illustrates the power of recursion. Think how would you implement this method without recursion.

Grading
  • (100%) Release Tests
Code Distribution

The assignment's code distribution is available here. Download it and import it as you have imported our class examples. The code distribution provides you with the following:

  • A package named sysImplementation - In this package you will find the Utilities.java class. You need to provide an implementation for each of the methods in this class. Information about each method can be found at javadoc.
  • A package named tests - Includes a shell file for your student tests.
Specifications
  1. Your methods must be recursive.
  2. You may not use any kind of loop construct (e.g., for, while, do while).
  3. You may not add any instance/static variables to the Utilities class. If you do, you will not learn the concepts required to do well in the final exam and you will lose significant credit in this exercise.
  4. Do not add comments nor define variables/methods in the Utilities.java file that include the words "for", "while" or "do", otherwise ALL your release tests will fail. Each test first checks whether the Utilities.java file has any instance of the words do, while, for. If that is the case, the test fails. You should see in the submit server a message similar to the following when a test fails due to the use of do, while, for: 
                    "java.lang.IllegalArgumentException: Source Code Using Iteration Statement at..."
  5. Your release test points could be adjusted if you do not follow the above specifications.
  6. You may not use Arrays class methods (except for your student tests).
  7. You may not use the ArrayList class except for the getListRowIndices method.
  8. You may use loops for your student tests.
  9. All your auxiliary methods should be defined as private.
  10. Do all your testing in your StudentTests.java file and do not add a main() to Utilities.java.
  11. Do not add any additional classes.
  12. It is important that you model/visualize the 2-dim array correctly. Draw a diagram so you can see what a particular value of x and y refers to. For example, we can visualize a 2-Dim array as: 
                         row0, col0    row0, col1   row0, col2

                     row1, col0    row1, col1   row1, col2

                     row2, col0    row2, col1   row2, col2

                     if x == 1 and y == 2, the cell we are referring to is row1, col2
  13. Make sure that you are calling your methods using x and y correctly (and not switching them by mistake).
  14. Test your code with a very small 2-Dim array (e.g., 2x3) where you try to replace each cell.
  15. Recursion is like some friends; at first, you don't understand them and you don't like them, but once you get used to them and understand them, you love them and cannot live without them :). Of course, you will always have friends that are just null reference exceptions. Yes, you can distribute this quote anywhere :)
